# Состояние проекта

Обновлено: 2026-09-30.

## Реализовано

- Этап 1: каркас Laravel 13.34, Vue 3/TypeScript/Vite 8, locked зависимости и CI для PHP 8.4/8.5 и Node.js 22.
- Независимое ядро `app/Domain/Lessons`: строгий документ версии 1, этапы и экземпляры блоков, доверенный registry, `core.text`, `core.image`, `core.single-choice`.
- Переводы содержания со стабильными ID вариантов; неизвестные поля/типы/версии, повторяющиеся ID и невалидные JSON/UTF-8 данные отклоняются.
- Неизменяемые released-снимки и заготовки, самостоятельные вставки экземпляров; публичные проекции исключают решения, заметки ведущего и происхождение заготовки.
- Временная информационная страница RU/DE в утверждённом стиле, с существующими иллюстрацией и логотипом. Это не готовый каталог или кабинет.
- Архитектура, контракт и инструкции запуска: `README.md`, `docs/ARCHITECTURE.md`, `docs/BLOCK_CONTRACT.md`, `docs/DEPLOYMENT.md`; подготовлен `scripts/deploy-plesk.sh`.
- Сохранены исходные ТЗ, руководство генерации, план моделей, дизайн и `OLD/kto-moi-blizhnii`; старый урок не является частью приложения и не определяет его архитектуру.

## Принятые решения

- Сначала движок, инструменты учителя, блоки и общая медиатека; учебное наполнение добавляется позднее.
- PHP приложения: минимум 8.4, локальная проверка на 8.4.25. Production по уточнению владельца: Plesk PHP 8.5.11 FPM, Node.js 22.23.3, MariaDB 10.6.23.
- Содержание будущей `LessonVersion` хранится одним JSON-документом с этапами/экземплярами; состояния, ответы и участники проведения хранятся отдельно. Выпуск версии не означает публикацию в каталоге.
- Языки документов независимы от RU/DE интерфейса. Полные переводы требуются для выпуска; работа редактора с неполными черновиками относится к следующему этапу.
- Медиассылки содержат идентичность объекта и конкретной версии файла; существование/права проверит будущая медиатека.
- Этап 1 использует файловые cache/session и sync queue; доменная БД и migrations не используются.
- Пульт должен поддерживать полностью скрываемое левое меню и отделение управления во вкладку/окно; это требования будущего UI, пока не реализованы.
- Основной агент: Sol Sehr hoch; независимые задачи делегируются Sol/Luna, Astra используется для целевой проверки. Разрешение пользователя сохраняется.

## Git и окружение

- Пустой GitHub-репозиторий подключён как `origin`: `https://github.com/VAtapin/lessons.git`; рабочая ветка — `main`.
- Последний связанный commit: первоначальный `Initialize lesson platform foundation`; точный hash содержащего этот статус commit определяется `git log -1 --format=%H -- PROJECT_STATUS.md`.
- SSH на порту 2377 проверен, фактический путь: `/var/www/vhosts/lessons.atapin.de/httpdocs`. Владелец подтвердил document root `httpdocs/public`.
- Пути Plesk PHP, Node и Composer подтверждены. Production-развёртывание и HTTP-проверка ещё не выполнены; перед публикацией исходники отправляются в Git.
- Учётные данные не входят в Git; `.env`, локальные служебные данные и результаты сборки исключены.

## Проверки

- PHP 8.4: PHPUnit — 61 тест, 101 assertion; Composer test и Pint прошли.
- Composer validate --strict, Vue typecheck и production build на Node 22.23.3 прошли. Bash syntax check deployment script прошёл.
- Браузер: страница и изображения загружаются; RU/DE переключается; при ширине 360 px горизонтального переполнения нет; console errors не обнаружены.
- Целевая проверка Astra: обнаруженный дефект UTF-8 исправлен и покрыт отрицательными тестами; других конкретных дефектов ядра не найдено.
- CI настроен; удалённый запуск пока не подтверждён. База, FPM и будущий runtime не считаются проверенными по локальным тестам.

## Следующий этап и ограничения

- Этап 2: минимальная связка редактора и renderer трёх базовых блоков, сохранение/версионирование и предпросмотр; без обязательного учебного урока.
- Нет конструктора, регистрации, проведения и истории занятий, таймера, соведущих, загрузки/хранения медиа, «волны добра», публичного каталога и фильтров.
- Квоты, срок хранения, целевая нагрузка, почта и поддерживаемые браузеры остаются решениями соответствующих этапов ТЗ.
- Изменения production выполняются через Git, без SFTP-загрузки исходников. Первый deployment и его результат записываются после фактической проверки.
