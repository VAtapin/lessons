# Контракт содержания и блоков, schemaVersion 1

Контракт реализован в `app/Domain/Lessons`. Это независимое от Laravel доменное ядро: оно проверяет содержание и значения ответов, фиксирует снимок и формирует представление для аудитории. Здесь нет HTTP, БД, конструктора, модерации или переходов занятия. Runtime и библиотека используют это ядро через application layer; наличие нового определения типа само по себе не подтверждает готовность его UI/runtime.

## Документ

`LessonDocument::fromArray($payload, BlockRegistry::core())` принимает ассоциативный PHP-массив, например результат `json_decode($json, true, flags: JSON_THROW_ON_ERROR)`. Ошибки контракта выбрасывают `ValidationException`. DTO документа, этапа и экземпляра блока — `final readonly`.

```json
{
  "id": "document-1",
  "schemaVersion": 1,
  "defaultLocale": "ru",
  "locales": ["ru", "de"],
  "content": {
    "ru": {"title": "Техническая сборка"},
    "de": {"title": "Technischer Aufbau"}
  },
  "stages": [{
    "id": "stage-1",
    "content": {
      "ru": {"title": "Вопрос", "notes": "Заметка ведущему"},
      "de": {"title": "Frage", "notes": "Hinweis für die Lehrkraft"}
    },
    "config": {"layout": "vertical", "durationSeconds": 60},
    "blocks": [{
      "id": "choice-1",
      "type": "core.single-choice",
      "schemaVersion": 1,
      "content": {
        "ru": {"question": "Выберите вариант", "options": [
          {"optionId": "first", "text": "Первый"},
          {"optionId": "second", "text": "Второй"}
        ]},
        "de": {"question": "Wähle eine Option", "options": [
          {"optionId": "first", "text": "Erste"},
          {"optionId": "second", "text": "Zweite"}
        ]}
      },
      "config": {"allowRepeat": false},
      "media": {},
      "solution": {"optionId": "first"}
    }]
  }]
}
```

- `id` документа идентифицирует редакцию содержания. Идентичность самого материала, владелец, доступ и persistent версии находятся вне доменного DTO.
- Документ содержит непустые упорядоченные списки этапов и блоков. Этапы имеют уникальные ID; ID блоков уникальны во всём документе. Пространства ID этапов и блоков раздельны. Порядок определяется массивами, не значениями ID.
- ID — 1–128 ASCII-символов: первый буквенно-цифровой, остальные буквенно-цифровые или `._:-`. UUID допустимы, но ядро не привязано к одному генератору. Выдача новых ID — обязанность вызывающего кода.
- `locales` — непустой список без повторов; `defaultLocale` входит в него. Поддерживаются теги вида `ru`, `de`, `de-DE`, `zh-Hant`. Начальные языки платформы этим примером не утверждаются.
- Все объекты `content` содержат ровно объявленные языки и обязательные поля. Неполный перевод отклоняется. Хранение незавершённого редакторского черновика с оценкой готовности перевода будет отдельной задачей; это ядро принимает только структурно полные документы.
- Название документа и этапа обязательны. Переводимые `notes` этапа необязательны и предназначены только учителю.
- У этапа `config` необязателен: по умолчанию `layout: vertical`; это единственный поддерживаемый макет. Необязательный `durationSeconds` — положительное целое рекомендуемое время, не таймер занятия.
- Неизвестные поля, зарегистрированные лишь в другой версии типы, строка `"1"` вместо целой версии, неверные формы и неожиданные значения отклоняются. Нет автоматического fallback языка или скрытых миграций.
- В PHP пустой объект после декодирования представляется `[]`; непустые объекты и списки различаются по ключам. Перед созданием DTO данные копируются без ссылок, содержат только JSON-совместимые значения, глубина ограничена 64 уровнями.

## Экземпляр и начальные типы

Обязательные поля блока: `id`, `type`, `schemaVersion`, `content`. Необязательные: `config`, `media`, `solution`, `origin`, `teacherNotes`. `config` получает значения по умолчанию; `media` — пустой объект; `solution` и `origin` — `null`. Явный `null` вместо `config`/`media`/`teacherNotes` отклоняется. Все три начальных типа поддерживают версию 1 и сохраняют прежнюю схему.

`teacherNotes` — закрытые переводы `{locale: string}` до 5000 Unicode-символов на локаль. Непустой объект содержит ровно объявленные языки, пустые строки допустимы. Отсутствующий/пустой объект не добавляется в `toArray()`, поэтому старые нормализованные снимки сохраняют форму. Teacher-проекция добавляет только строку выбранного языка; остальные аудитории не получают поле. Независимая копия блока/заготовки сохраняет заметки.

| Тип | Переводимый `content[locale]` | `config` | `media` | `solution` |
| --- | --- | --- | --- | --- |
| `core.text` | Обязательный непустой `text` | Только `format: plain`, по умолчанию `plain` | Пустой объект | Только `null` |
| `core.image` | Обязательный непустой `alt`, необязательный `caption` (может быть пустым) | `fit: contain` или `cover`, по умолчанию `contain` | `image: {assetId, versionId}`, оба стабильные ID | Только `null` |
| `core.single-choice` | Непустой `question`, список минимум двух `options: [{optionId, text}]` | Boolean `allowRepeat`, по умолчанию `false` | Пустой объект | `null` либо `{optionId}` существующего варианта |

Текст трактуется как обычный текст. Любой будущий renderer должен экранировать его; доменный DTO не выполняет HTML-рендеринг и не предоставляет безопасный HTML. Ограниченное форматирование можно добавить совместимой явно проверяемой версией.

Варианты вопроса идентифицируются `optionId`, а не текстом или позицией. В каждой локали ID уникальны; набор ID совпадает во всех локалях. Переводы могут менять текст и порядок. Решение едино и ссылается на ID варианта. Поля вроде `correct` внутри вариантов, `solution` внутри публичного `config` или URL внутри `media` неизвестны и отклоняются.

Медиа содержит ссылку на конкретную версию файла. Ядро проверяет форму ссылки, но не существование, владение, доступность файла или права использования; эти проверки выполняет application MediaCatalogue с owner context.

## Дополнительные определения этапа 5

В том же registry зарегистрированы `core.text@2`, `core.prompt@1`, `core.multiple-choice@1`, `core.poll@1`, `core.free-response@1`, `core.sequence@1`, `core.matching@1`, `core.roles@1` и `core.signals@1`. Строгие формы/defaults/value DTO перечислены в [STAGE5_API.md](STAGE5_API.md). Text@2 поддерживает paragraphs/list/quote как безопасное расположение обычного текста, а не HTML; text@1 не преобразуется в новую версию при чтении.

Пределы нового содержания: title/source text@2 — до 5000 Unicode-символов (могут быть пустыми), основной text@2 — непустой до 50000; prompt/question и подписи элементов новых типов — непустые до 5000. Старые типы сохраняют прежние правила. Options/items — 2–12, roles — 1–12; вместимость роли — strict integer 1–100. Free-response maxLength — strict integer 1–1000, default 500; ответ из одних Unicode whitespace отклоняется, допустимый исходный текст не обрезается и не форматируется.

Наборы IDs совпадают во всех переводах и остаются case-sensitive. Multiple-choice нормализует множество IDs сортировкой, sequence сохраняет порядок полной перестановки, matching проверяет взаимно однозначные полные пары и нормализует по leftId. Roles проверяет ID/nullable release, но не занятость места; signals принимает только boolean ready/question, не клиентский acknowledged. Места, права, модерацию и состояние упражнения проверяет runtime.

## Регистрация доверенного расширения

`BlockRegistry::core()` регистрирует начальные и дополнительные определения. Новый тип реализует `BlockType`: `id(): string`, `schemaVersion(): int`, `defaults(): array` и `validate(BlockInstance $block, array $locales): void`. `register()` отклоняет повтор пары `(id, schemaVersion)`; `resolve()` отклоняет неизвестную пару. Разные явно зарегистрированные версии типа могут сосуществовать. Второго каталога серверных типов нет.

Расширение поставляется доверенным кодом и проходит обычные проверки проекта. Документ не содержит имён классов, исполняемых скриптов или инструкций загрузки. Валидатор должен проверять все формы/поля собственного `content`, `config`, `media`, `solution`; публичные поля не должны содержать закрытые решения или заметки. Для нового несовместимого формата регистрируется новая версия. Ядро не преобразует старое содержание при чтении.

BlockType охватывает содержание. Optional `InteractiveBlockType extends BlockType` добавляет `validateAnswer(BlockInstance,array):array`, `grade(BlockInstance,array):?bool`, `publicResult(BlockInstance):?array` и `initialState():string`. Он реализован single-choice и новыми интерактивными определениями. Валидация возвращает detached нормализованный value; grade принимает такой value и возвращает true/false/null. Poll/free-response/roles/signals не имеют автоматического правильного решения. PublicResult возвращает только whitelist решения; application layer разрешает его выдачу лишь после reveal. InitialState — open у legacy single-choice/roles/signals, prepared у остальных. Переходы состояния, хранение ответов и anonymous aggregates не выполняются этим интерфейсом.

## Проекции и закрытые данные

```php
$registry = BlockRegistry::core();
$document = LessonDocument::fromArray($payload, $registry);
$student = $document->project(Audience::Student, 'de');
$projector = $document->project(Audience::Projector, 'de');
$teacher = $document->project(Audience::Teacher, 'de');
```

`Audience` — enum с `Teacher`, `Projector`, `Student`. `project()` требует явную доступную локаль. Проекция содержит только этот перевод и сохраняет технические ID. `solution` блока, `teacherNotes` и `notes` этапа добавляются только учителю; происхождение заготовки не включается в проекции. Доменные проектор и ученик получают одинаковое публичное содержание; разрешённое runtime состояние добавляется после него отдельно.

`toArray()` и сами DTO содержат полное содержимое для сохранения, включая закрытые данные. Их нельзя сериализовать непосредственно в публичный ответ. HTTP-слой определяет аудиторию из проверенных сервером прав и использует `project()`. Сам enum не является проверкой авторизации, а teacher-проекция не является разрешением её получить. Публичные доменные проекции всегда исключают `solution`; разрешённое раскрытие отдельного whitelisted результата находится в runtime, не меняет исходный документ.

## Снимки и заготовки

`new ReleasedLesson($releaseId, $document)` фиксирует неизменяемый валидированный документ. Личная выпущенная версия не означает публикацию в каталоге. `newDraft($newDocumentId)` возвращает независимый изменяемый массив с новым ID редакции, сохраняя ID этапов/блоков. После правок он снова проходит `LessonDocument::fromArray`. Снимок нельзя изменить через вложенные readonly-поля, исходные PHP references или правки возвращённого массива. Persistent выпуск/хранение и права доступа реализуются application layer и не входят в этот DTO.

`new BlockTemplate($templateId, $versionId, $validatedBlock)` представляет снимок редакции заготовки. `instantiate($newInstanceId)` создаёт другой readonly-экземпляр, копирует содержание/настройки/медиа/teacherNotes и записывает `origin: {templateId, versionId}`. ID исходного экземпляра повторно использовать нельзя; уникальность нескольких вставок проверяет документ. Для правки экземпляра используется его `toArray()` и повторная валидация; заготовка и другие вставки сохраняются. Медиа продолжает ссылаться на ту же версию файла. Persistent metadata, поиск, доступ и версии заготовки находятся в application library этапа 4.

## Проверки

После установки зависимостей проекта:

```bash
php vendor/bin/phpunit tests/Unit/Domain
```

Тесты проверяют начальные/новые типы и defaults, round-trip, строгие формы и пределы, неизвестные поля/типы/версии, дубли ID, полноту переводов, стабильность IDs при переводе/переупорядочении, нормализацию/оценку ответов, whitelist результатов, закрытые проекции/teacherNotes, отсутствие fallback, неизменность снимка и независимость вставок заготовки. Эти unit-тесты не поднимают Laravel, БД или занятие и не подтверждают завершение всего этапа 5.

## Повторяемая картинка для счёта

`core.presentation@1` поддерживает `config.kind = picture-count` через существующий renderer и команды проведения. Обязательна `media.image` с точной парой asset/version. В `content[locale].modes` находятся 1–8 режимов с обязательными `modeId`, `text`, `count` и optional `label`, `title`. `count` — целое 0–min(20, maxItems); идентичности и количества совпадают во всех переводах. У других presentation kinds поле count запрещено. До первой команды показан первый режим.

Только ведущий меняет режим через существующую `presentation.mode`; UUID receipt, revision и права остаются обязательными. Ученики не могут отправлять ответы этому kind. Сохранённый режим одинаков в ученической и проекторной проекции, включая заголовок. Изображение проверяется обычными media ownership/scoped-file правилами, отображается в preview и общих заготовках, учитывается в usage и SHA256 installation receipt. Конструктор позволяет менять изображение, подписи и количество; изменение количества синхронизируется между переводами.

Optional `stage.config.theme` допускает `green`, `terracotta`, `slate`, `lavender`; документы без настройки сохраняют зелёную палитру. Настройка влияет на сцену и завершение, не меняя содержание или сохранённые ответы.


## Таблица в раскрываемом блоке

Optional `content[locale].table` допустима только у `core.presentation@1 / reveal`: обязательны `headers` (2–6 непустых строк, до 200 символов) и `rows` (1–12 строк, ячейки до 500 символов). Каждая строка имеет столько ячеек, сколько заголовков; размеры совпадают во всех переводах. Неизвестные поля и значения другого типа запрещены. Данные редактируются как обычные переводы, без HTML и отдельного renderer.

`presentation.toggle` сохраняет прежние проверки прав, UUID/revision. Пока блок скрыт, runtime удаляет таблицу, текст, цитату и источник из публичной проекции; повторное скрытие также удаляет таблицу. Preview показывает содержимое блока. Интерфейс выводит semantic table с caption, col/row headers; ученики не управляют раскрытием.
