# Этап 3: проведение и отделяемый пульт

Согласованный контракт реализации. Это дополнение к существующему runtime, не второй движок.

## Серверное состояние

- Существующие занятия остаются `running`. Создание принимает необязательное `prepare: true` для состояния `prepared`; без флага поведение этапа 2 сохраняется. Редактор создаёт подготовленное занятие, пульт явно начинает его.
- Состояния: `prepared`, `running`, `paused`, `finished`. Пауза занятия блокирует ответы и останавливает работавший таймер; продолжение возобновляет только таймер, остановленный этой паузой. Независимая пауза таймера не блокирует ответы. Завершение окончательное, блокирует ответы/новых участников; существующий участник сохраняет доступ к собственному результату.
- Навигация сохраняет ответы и не перезапускает таймер. Таймер запускается явной командой на 1–7200 секунд; рекомендация этапа только заполняет поле. Истечение таймера не завершает занятие.
- Общие поля всех проекций: `status`, `serverNow` (ISO UTC), `timer: {status: idle|running|paused|expired, endsAt: string|null, remainingSeconds: number}`, `message: string|null`, `wave: {id, expiresAt}|null`. Публичная wave возвращается только до истечения шести секунд. Нет публичного журнала команд или полномочий.
- Teacher дополнительно получает `publicStage` (точную projector-проекцию активного этапа), `joinUrl` (с кодом в query), участников `{id,name,connected,lastSeenAt}`. Поле `stage` ученика и `ownAnswers` сохраняют существующий контракт. При GET ученика активность обновляется не чаще одного раза за пять секунд; connected означает активность за последние 20 секунд, не доказательство постоянного сетевого соединения. Значения вынести в config.

## Команды

`POST /api/studio/sessions/{id}/commands`:

```json
{"commandId":"UUID","expectedRevision":1,"action":"stage","payload":{"stageId":"stage-id"}}
```

- Действия: `begin`, `pause`, `resume`, `finish`, `stage` (`stageId`), `timer.start` (`seconds`), `timer.pause`, `timer.resume`, `timer.clear`, `message.set` (`text`, обычный текст до 1000 символов), `message.clear`, `wave`. Для действий без параметров payload — пустой объект.
- Авторизация до чтения журнала; row lock занятия; unique(session,commandId). Повтор того же UUID и исходного тела возвращает актуальный teacher state с `acknowledgedCommandId`, без повторного эффекта/увеличения revision. Другое тело с тем же UUID — `command_conflict` 409. Устаревшая revision — `revision_conflict` 409 с текущим teacher state; недопустимое состояние — `invalid_state` 409. Не сохранять отклонённые команды как выполненные.
- Все успешные новые команды повышают revision ровно один раз. Старая stage API сохраняется и использует ту же бизнес-логику навигации. Ответы всё ещё идемпотентны по участнику/блоку; повторы попытки блока не вводятся до соответствующих интерактивных типов.
- Таймер/состояния/дедупликация сохраняются в БД, время берётся с сервера. Окна не являются источником истины.

## UI

- Страница `/{locale}/control/{sessionId}` имеет ту же проверку владельца, что teach. Компактная страница не показывает глобальное меню/большой preview. TeacherPanel принимает compact prop.
- Новая вкладка/окно открывается только нажатием. Handshake и heartbeat через BroadcastChannel с конкретным случайным instance ID в query; parent скрывает встроенные инструменты только после успешного подключения авторизованного пульта. Таймаут/blocked popup сохраняет встроенное управление и показывает альтернативу вкладки. Возврат/потеря heartbeat возвращает управление. Закрытие parent не лишает child серверного доступа.
- Polling и commands сохраняют защиту от устаревших GET. При потере связи показывать статус, сохранять последнее подтверждённое состояние, не объявлять команды выполненными. При неопределённом POST повторять исходный UUID/тело; после конфликта обновить серверное состояние, не повторять действие автоматически.
- QR создаётся локально из joinUrl, без внешнего сервиса. Join читает code из query и требует имя/явное присоединение.
- Волну показывать один раз по ID, только пока она действует; sessionStorage предотвращает повтор при reload. reduced-motion получает спокойное сообщение. Локальный отсчёт корректируется serverNow, не управляет занятиями.
- RU/DE строки; бумажный/янтарный утверждённый стиль. Список этапов можно свернуть. Ответы/закрытые заметки доступны в компактном пульте.

## Проверки и deployment

Feature tests: ownership/CSRF, вся state machine, независимая пауза таймера, истечение, дедупликация/конфликты/rollback, обратная навигация с ответами, две независимые комнаты, закрытые данные, активность и истечение wave. UI: embedded/tab/popup/return/fallback, reload/reconnect, узкие экраны, клавиатура, реальный QR.

Новые migrations только additive. Production уже содержит данные: перед migration нужен проверенный приватный backup вне public/httpdocs, без пароля в argv/логе/Git. Initial-empty flag не применять повторно. Restore требует отдельной команды и проверки, автоматически не запускать.
